# 하네스 진화 참조 — RRSI·Harness² 흡수 (2026-11-22)

출처 스냅샷 검토: github.com/google-research/rrsi (paper 2609.24972) ·
github.com/google-research/harness2 (paper 2610.14224) — 둘 다 "모델 고정, 하네스(프롬프트·도구·기억·오케스트레이션) 진화" 연구.

## RRSI — 정칙화된 하네스 탐색 (제안측·선택측 규칙)

### 제안측 정칙화 (편집을 어떻게 제안할지)
- **어닐링 편집 예산**: 후보 하나가 묶을 수 있는 독립 편집 수를 단계마다 제한 — 초기엔 넓게, 후기엔 작게.
- **전체 편집 이력 조건화**: 제안자는 거짓 판명된 가설을 다시 뽑지 않는다(이력 = 1 JSONL/edit: 컴포넌트·가설·측정된 점수·비용 변화·판정).
- **정체(stall) 시 미사용 컴포넌트로 리디렉션**: 진전이 없으면 한 번도 건드리지 않은 영역을 탐색하도록 강제.

### 선택측 정칙화 (무엇을 채택할지) — **dgate 벤치마크 프로토콜에 직접 적용**
- **잡음 조정 바닥(floor)**: `S' ≥ S* − δ` 미만은 후보 자격 없음 — 평가 분산 이내의 개선은 개선이 아니다. 채택은 `argmax(가능 후보)` 아니면 현행 유지.
- **비용 규칙**: 이득이 δ 초과면 `Δcost ≤ β0 + β1·ΔS` 예산 안에서만 채택 — 추가 토큰은 측정된 이득이 지불해야 한다. 이득이 δ 이내면 조형점수 `w_s·ΔS − w_c·ΔC + w_n·신규성 > 0`일 때만.
- **평가 전 비평가(critic) 누수 검사**: 벤치마트 특화 로직·우회 편법을 스크린 — 점수를 올리지만 일반화되지 않는 편집 차단(mandela 누수 감사와 동일 원리).
- **도움을 멈춘 컴포넌트 가지치기** — "필요 없다"의 근거 있는 제거.

### 운영 형태
- 후보는 전부 **git worktree**에서 수정·스크린·평가, 채택 시 `evolve/<도메인>` 브랜치 fast-forward — **현행 하네스가 항상 커밋 하나로 audit 가능**.
- 제안자·분석가·비평가 프롬프트는 평범한 파일 — 버전관리 대상.

## Harness² — 열린 세계 재귀 하네싱

- **과제 수준 재귀 (Propose–Probe–Compose)**: 정답 없이 같은 과제에서 편집 효과를 탐침(probe)하고, **실행 간 행동 대조(contrast)** 로 개선 하네스를 합성. 정답 라벨이 없는 운영 환경(paperwork)에서 하네스 변경을 검증하는 패턴.
- **하네싱 수준 재귀**: 채택된 하네스 + **증거가 붙은 교훈(lesson)** 으로 상시 '개선 하네스'를 갱신해 다음 과제의 정제를 안내 — LESSONS.md·ICM·mistology가 지향하는 것의 학술적 형식화.
- 한 단계만으로 GLM-5·Gemini 3.5 Flash 기준 +4.5~11.8pt — 재귀 예산을 늘리면 추가 이득.

## dgate 적용

### 벤치마크 프로토콜 강화 (docs/decision-gate-references.md에 반영)
1. **잡음 바닥**: 게이트 on/off 비교의 이득이 평가 분산 δ 이내면 "차이 없음" 판정 — 채택 금지.
2. **비용 규칙**: 절감액이 분류 비용+추가 토큰을 상환하지 못하면 on 전환 금지(예산식 β0+β1·ΔS).
3. **누수 스크린**: 벤치마크 과제를 우회하는 게이트/워커 편집은 평가 전 기각.

### 하네스 변경 관행 (우리 체계에 이미 있는 것의 이름 붙이기)
- 후보 = worktree + 브랜치, 현행 = 커밋 — dgate 워크트리 체크포인트·배차 관례와 동일. 이제 "하네스 편집 후보"에도 같은 형태 적용: **스킬·지침·프롬프트 변경도 게이트 밖에서 직접 수정하지 않고 후보 검증 후 채택**.
- 교훈 저장은 이미 ICM·LESSONS·mistology로 운영 — RRSI의 "가설별 판정 기록" 형식(컴포넌트·가설·측정·판정)을 교훈 항목 스키마로 권장.

## 미채택
- 두 프레임워크의 자동 탐색 루프(제안자·비평가 자동화): 우리 하네스 진화는 사람 승인 게이트를 유지 — 자동 채택은 누수·비용 규칙이 실측 기반으로 서긴 전에 도입하지 않는다.
