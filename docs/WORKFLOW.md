# 저장소·PR 워크플로우 (다중 Task 병렬 개발 플레이북)

저장소 단위로 여러 task를 나눠 개발하고 PR로 병합할 때 적용하는 표준 워크플로우다. 단순 질문이나 즉석 수정에는 강요하지 않는다.

## 요약 순서

1. **PRD 뼈대 작성** — 무엇을 만들지, task를 어떻게 나눌지 먼저 정리한다.
2. **첫 task 시범 (소유주 직접)** — 소유주가 첫 task를 직접 수행해 본보기를 만든다.
3. **둘째 task부터 워크플로우 위임** — 시범 패턴을 따라 에이전트가 자율 진행한다.

## 적용 시점과 범위

- 계획(PRD) 수립, task 분해, 구현 위임, PR 개설, 병합 직전에 이 문서의 원칙을 적용한다.
- 이슈·PR 워크플로우는 **GitHub 원격 저장소 연결이 전제**다. 원격 없이 로컬만으로 다중 task 개발을 시작하지 않는다.
- 단순 질문·즉석 수정에는 이 플레이북을 강요하지 않는다. 저장소 단위로 task를 나눠 개발·위임할 때만 적용한다.

## PRD task 분리 기준

- **최우선 기준: task끼리 건드리는 파일·폴더 영역이 겹치지 않게 나눈다.** 영역이 겹치면 병렬 실행이 아니라 충돌 처리가 된다.
- 불가피하게 영역이 겹칠 때는 사전에 **병합 순서**, **단독 담당 지정**, 또는 **기준 공유 파일**을 PRD에 명시한다.
- PRD 경계 설계에 시간을 들여야 뒤의 병렬 실행이 빨라진다. 경계가 흐리면 병렬 이득이 충돌 해소 비용으로 상쇄된다.

## 첫 task — 소유주 시범

- 첫 task는 **소유주가 직접** 꼼꼼하게 세부 항목을 작성한다.
- 항목별 PR을 하나씩 올리며 **브랜치명 규칙, 커밋 단위, PR 크기, PR 본문 형식**의 본보기를 만든다.
- 시범 없이 위임부터 시작하지 않는다. 에이전트는 이 시범 패턴을 그대로 따라하게 된다.

## 둘째 task부터 — 워크플로우 위임

- 시범 패턴을 따라 **세부 항목 작성 → 구현 → 브랜치 commit/push → PR 개설**까지 에이전트가 재승인 없이 자율 진행한다.
- 단, **main 병합과 배포는 반드시 별도 승인 지점**으로 유지한다. 자율 진행의 끝은 PR 개설이다.
- "워크트리 최대한 이용해서" 지시가 있으면 `git worktree`로 파일 영역이 겹치지 않는 병렬 작업 단위를 분해해 동시 실행한다. dgate 환경에서는 `dg worktree remove`의 sha256 체크포인트 게이트와 결합해 안전하게 정리한다.

## 작업 중 보완 — 이슈와 자동화

- 작업 중 떠오르는 수정 사항은 흐름을 끊지 말고 **GitHub 이슈로 등록**한다(모바일 앱 포함). 나중에 task·PR로 전환한다.
- 반복해서 일어나는 실수·충돌은 커밋 시점 자동화(git hook 등)로 예방한다. 검증 단계 이전에 커밋 자체에서 차단하는 게 비용이 가장 싸다.

## 리뷰와 CI 비용 통제

- 외부 자동 PR 리뷰 도구(예: open-code-review)는 **PR마다 돌리지 않고 main 병합 시에만** 사용한다.
- CI는 **로컬에서 PR 단위로 먼저** 실행하고, 원격 GitHub CI는 **배치(묶음) 단위로만** 돌린다. PR마다 원격 CI를 돌리면 대기열 병목과 비용이 커진다.

## dgate 기능 매핑표

| 워크플로우 항목 | dgate 기능 |
| --- | --- |
| PRD 비겹침 워크트리 병렬 실행 | `git worktree` + `dg worktree remove` (sha256 체크포인트 게이트) |
| 위임 실행 감시 | `dg wrap` (스톨 와치독) |
| 독립 검증 | `dg backprop` (검증 verdict 반영) |
| 반복 실수 자동화 후보 발굴 | `dg report` / mistology |
