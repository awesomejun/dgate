# 자율 실행 계약 — pstack 흡수 (2026-11-21)

장기 자율 실행·검증·자동화에 가져올 계약만 뽑은 참조 문서.
출처: github.com/cursor/plugins pstack(poteto, MIT) 스냅샷 검토.

## 오버나잇 인계 계약
- 신뢰 선조건 4개를 충족해야 무인 루프 허용: (1) 사람이 한 번 해봤거나 지켜봤다 (2) 에이전트가 사람과 같은 도구·신호(검증·프로파일러·로그)를 갖는다 (3) 모든 단계가 자기 증명을 하고 기준 미달 시 라인을 멈춘다 (4) 반복 실패를 도구·스킬·검사로 바꿔뒀다. 미충족이면 지켜보며 실행.
- 인계 문장 5요소: 세션 오버라이드("잔다"=더 묻지 않기) · **done-means 술어**(반복마다 검사 가능한 완료 조건) · 격리 worktree · 미리 답해둔 권한("커밋 전에 묻지 마라") · **탈출구**(몇 시간째 막히면 멈추고 이유를 기록 — 8시간의 창의적 목표 재해석보다 낫다).
- **기간은 완료 조건이 아니다.** "4시간 작업해라"는 검사할 것이 없다. 루프에는 통과/실패 가능한 술어를 준다.

## 루프 규율
- 한 반복 = 최소 변경 1 → 실제 산출물 검증 1 → 결정 로그 1줄. 진전 없으면 버린다(디스카드), 실어 가지 않는다.
- 고원에 닿으면 정지가 아니라 피벗. **완료 조건은 승리 선언을 위해 조용히 완화되지 않는다.**

## 아침 감사
- 결정 로그는 TSV 한 줄: 시각·단계·결정·이유·증거 포인터·결과.
- 요약 전에 **다른 모델 계열 리뷰어**가 로그와 트랜스크립트를 읽고 'Attention' 섹션(감사할 지점)으로 끝낸다 — 밤 전체를 다시 읽지 않고 결정을 감사한다.

## 검증 경제학
- 오너는 자기 판정으로 머지하지 않는다. 머지되는 패치에 대한 깨끗한 판정만 머지를 승인한다.
- PR마다 fresh 검증자; 이후 리베이스·사소한 수정엔 검증자 1명, 새 동작·큰 diff에만 스웜 전체 재투입.

## 단계별 정지선·증거 (자동화)
- 유지보수 파이프라인(분류→재현→수정→검증)은 각 단계가 라인을 멈출 수 있다: 분류는 예상 동작으로 기각 가능, 재현은 재현 실패로 종결 가능, 수정은 위험 판단으로 거부 가능. 나쁜 일이 다음 단계로 넘어가 폐비용을 키우기 전에 막는다.
- 모든 단계는 증거를 인계한다: 재현은 고장 상태 스크린샷·영상, 수정은 before/after 증명. 사람이 코드 한 줄 안 읽고도 올바른 것을 고쳤는지 확인 가능하게.
- 자동화 안전 규칙(benny): 트리거 정체성(채널·스레드 식별자)은 불변, 불일치 시 기록 없이 정지. 발신자는 코디네이터뿐, 위임 워커는 읽기전용+쓰기 행위 명시 금지. 진행 메시지 없음. 판정은 설정된 마커 정확히 1개로 끝낸다.

## 삭제주의 리뷰 keep-list (comment-sicko)
- 코멘트 검토는 기본 삭제, 예외만 생존: 법적·라이선스 헤더 / 외부 의존성·플랫폼이 강제하는 비명시 동작 / `prettier-ignore` / 공개 API 계약 문서 / 제약을 설명하는 이슈·RFC 링크. 확신 없으면 삭제.
- `@ts-ignore`·`eslint-disable`류는 룰을 조사해 실결함 보호면 삭제+해당 심볼 마킹. 리뷰어는 보고만 하고 코드는 건드리지 않는다.

## dgate 매핑
- done-means·탈출구·결정 로그는 워커 지시문(목표·범위·금지·완료 기준·보고) 계약에 그대로 추가 가능.
- 검증 경제학·정지선은 dgate 독립 검증 관례(연속 오류 2회 split 강제)와 같은 방향 — 참조 근거로 사용.
